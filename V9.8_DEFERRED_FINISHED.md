# V9.8 — Deferred items finished

Closing out the three items that were explicitly deferred from earlier slices.

## 1. Master data IMPORT (was deferred from V9.4 hotfix / Slice 1)
- New endpoint: POST /api/templates/master-import/{client_id}
- New service: app/services/templates_import_service.py — parses the same Excel
  structure that templates_service.py generates (round-trip safe).
- Upsert semantics by natural key:
    Directors        — match by name (case-insensitive, trimmed)
    Shareholders     — match by name
    Custom CoA       — match by code (uppercase)
    Policies         — match by policy_number
    Client Master    — update Client row's fields in place
- Header parsing finds columns by name (not by index) → resilient to column
  reordering in future template versions.
- Frontend: client page header now has an "Import master data" button (next to
  "Export master data"). Opens a dialog with drag-drop file zone. After import,
  the dialog shows per-sheet counts (created / updated) and refreshes the page.
- Hint shown: "If you're using the blank template, delete the sample rows
  before uploading — otherwise they will be imported as real records."

## 2. PPE template IMPORT + move PPE controls to PPE area (was deferred from V9.4 / Slice 1)
- New endpoint: POST /api/templates/ppe-import/{project_id}
- Upsert by (project_id, coa_code) — updates the 12 amount columns.
- PPE template DOWNLOAD button moved off the client-page header and onto the
  PPE card itself (where it belongs — PPE is a project concern, not client).
- New "Import PPE" button next to the template button.
- Confirmation dialog shows created / updated counts after import.

## 3. Audit search + filter (was a watch-for item)
- Added a filter bar above the audit table:
    - Status pills: All / Proposed / Approved / Posted
    - Free-text search box matching description, Dr CoA, or Cr CoA
- Bar only appears when there are entries (clean empty state stays untouched).

## What's still deferred (intentional)
- Alembic migrations — still `rm data/tce.db` on local schema changes.
  Supabase prod handles new tables via lifespan startup; column changes need a
  proper migration before V2 GA.
- Auto-map keyword tuning — wait for real tester TBs before adjusting
  LEDGER_KEYWORDS. Tuning without real data is guesswork.
- EPS field shape — render adapts to backend; if testers see "—" everywhere
  on the EPS tab we'll see the shape mismatch and fix in one line.
