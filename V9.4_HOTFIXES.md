# V9.4 — Hotfixes from real-use feedback

Two critical issues found during testing on the live deploy, both fixed.

## Fix 1 — Sub-codes not loading on mapping page (critical bug)

### What you saw
Pick a Major Code like "PL-01 Revenue from Operations" on the mapping page →
the Sub-code dropdown only shows "-- Sub --" with no options. Same problem for
"PL-02 Other Income" and several other categories.

### Root cause
`app/main.py` was deriving the "major code" set from `level in (2, 3)`, and the
sub→major map (`s2m`) only included codes where `level > 3`. But the CoA hierarchy
is uneven: PL-01 (level 2) has only level-3 children (PL-01-01..04). Those level-3
codes were being put in the **major** dropdown AND excluded from the **sub** dropdown
— so picking PL-01 found zero subs because PL-01-01..04 were misclassified.

### Fix
Build `s2m` from the actual `parent_code` field instead of from level math. A
code is a "major" iff some other code lists it as `parent_code`. Walks up the
tree if the immediate parent isn't a major itself (handles 3-level chains).

Result:
- 27 majors (was a confused mix)
- 211 mappable sub-codes (was missing ~70)
- PL-01 → shows 4 revenue subs
- PL-02 → shows 10 other-income subs
- PL-04-07 → shows 27 expense subs

### Side effect for the screenshot you sent
"Service Income- Domestic" was auto-mapped to PL-01-03 correctly (keyword rule
"service income" → PL-01-03), but the page couldn't render the row coherently
because the OLD s2m didn't include PL-01-03 in subs. Now the page shows
Major=PL-01, Sub=PL-01-03 (selected), with the other 3 revenue subs listed.

## Fix 2 — Client delete with name-confirmation safety

### Why
There was no client-delete endpoint at all. Testers can't recover from typos
or test-data without DB surgery.

### How
- New `DELETE /api/clients/{id}` requires `{"confirm_name": "<exact name>"}` payload.
- Wrong name → 400 with the exact name re-displayed so user can retype.
- Cascades to projects, directors, shareholders, custom CoA, policies (already
  configured in models).
- Multi-tenant aware: Firm B trying to delete Firm A's client gets 404 (no leak).
- UI: a small 🗑 button appears on hover on each client card on firm dashboard.
  Clicking it opens a modal requiring the user to type the client name exactly
  before the "Permanently delete client" button enables.

## Verified
- 97/97 main regression
- 11/11 multi-tenant isolation
- Manual: 5 delete scenarios (correct/wrong/empty/missing/cross-firm) — all behave correctly
